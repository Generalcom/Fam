# Family Circle

Opt-in family location sharing. Expo (React Native) app with a Supabase backend.

- Members join a private **circle** with an invite code and see each other on a map in real time.
- Anyone can pause sharing at any time; pausing deletes their stored location immediately.
- Only the latest position is stored, never a history. Visibility is enforced in Postgres (row level security), not just in the app.

## Setup

1. Create a project at [supabase.com](https://supabase.com), then open **SQL Editor** and run [supabase/schema.sql](supabase/schema.sql).
1a. For enrolment (people's icons and the identity check), also run [supabase/enrolment.sql](supabase/enrolment.sql) (safe to run more than once). Until you do, the app shows "One more setup step". It adds the icon column, the `kyc_submissions` table and a private `kyc` storage bucket; read the comments at the top of that file for who can read what and how a reviewer approves or rejects a person.
1b. For safety zones, also run [supabase/safety-zones.sql](supabase/safety-zones.sql) (safe to run more than once). Until you do, the app works but shows "Safety zones need one more setup step".
2. For sign-in without email, enable **Authentication > Sign In / Providers > Allow anonymous sign-ins**. The app's default "Get started" flow uses it. Guest accounts are lost on sign-out or app data clear. For email accounts, turn off **Confirm email** while testing (otherwise sign-up needs an email click first).
3. Copy `.env.example` to `.env` and fill in the project URL and anon key (Project Settings > API).
4. For the Google Maps picture on the location card, set `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY` in `.env`:
   1. In [Google Cloud Console](https://console.cloud.google.com) create (or pick) a project and attach a billing account. The Static APIs need one, though Google's monthly free credit normally covers light use.
   2. **APIs & Services > Library**: enable **Maps Static API** and **Street View Static API**.
   3. **APIs & Services > Credentials > Create credentials > API key**.
   4. Restrict the key (**API restrictions**: only those two APIs). Anything starting with `EXPO_PUBLIC_` is bundled into the app, so anyone can extract it. Add an application restriction too (Android package + SHA-1 / iOS bundle id) for a published build, and set a low daily quota and a budget alert so a leaked key cannot run up a bill. Expo Go cannot be restricted by app, so use a separate, quota-limited key for development.
   5. Restart with `npx expo start -c` (env values are read when the bundle is built).
   Without a key the card falls back to the building's Wikipedia photo, and shows a hint in development. No OpenStreetMap picture is used.
5. `npm install`, then `npx expo start`.

## Running on a phone

- **Expo Go**: works for accounts, circles, the map and location sharing while the app is open. Background sharing is not available in Expo Go.
- **Development build** (needed for background sharing): `npx expo run:android` or `npx expo run:ios` (iOS needs a Mac), or `eas build --profile development`.
- **Map**: OpenStreetMap data from [OpenFreeMap](https://openfreemap.org), drawn with MapLibre GL inside a WebView ([src/components/osm-map.tsx](src/components/osm-map.tsx)), so no API key is needed. The map never shows a world or continent view: it opens already at the user's place, found without waiting for GPS (the phone's cached position, else the position this app last saved on the phone, else the city of the phone's time zone from [src/constants/timezones.ts](src/constants/timezones.ts), generated from the IANA tz database), and it cannot be zoomed out past regional scale (`minZoom: 5`). If none of those is known it shows "Finding your location…" until the first GPS fix. The saved position stays on the phone and is deleted on sign-out. No sharing indicator or credit icon is drawn on the map (by request): the sharing switch is in Settings, and the OpenStreetMap / OpenFreeMap / OpenMapTiles credits are under Settings > Map credits. Their licences require the credit to be readily available, so keep it reachable in any public release. Only you are on the map at the start. The family orb lists the people in the circle (with when they were last seen, never how far away they are); choosing one shows just that person, with you, and opens their location card, and closing the card hides them again. The button on the map centres it on you. (The safety banner still warns if anyone is in or near a red or be-aware zone, and tapping it opens that person.) Tapping a person in the family list opens a location card ([src/components/place-card.tsx](src/components/place-card.tsx)): a picture, whether they are inside, next to or away from the building, the building's name, height and floors, the street address, the coordinates (with copy) and an "Open in Google Maps" button that links to their coordinates. The picture is a Google Maps preview (satellite view with a pin, from the Maps Static API), switchable to Street View when Google has imagery there (checked first with the free metadata call) and to the building's Wikipedia / Wikimedia Commons photo, with its photographer and licence credit, when it has one. All of the Google pictures need the API key from Setup step 4; if the key is missing or Google refuses a picture, that choice disappears and the next one is shown. The picture only reloads when the person moves more than 50 m, to keep Google requests (and cost) down. Address and building details come from OpenStreetMap's Nominatim (the building by its map id, else a reverse lookup), which needs no key. Nominatim's public server is for light use only (one request a second, cached here), so a real launch needs a paid provider or your own server. Safety zones: press and hold the map to add a circle marked red (avoid) or be-aware (take care), with a radius, name and optional note. Zones are stored in the `safety_zones` table, private to the family circle (row level security), and drawn on the map under the buildings. Anyone in the circle can add one; the person who added it or the circle admin can remove it (Family tab). A banner warns whenever someone, including you, is in or near a zone (a GPS reading counts as "near" if its uncertainty reaches the zone), the family orb gets a red or amber badge, and the family list and location card say which zone. Rows with no circle (`circle_id` null) are shared with every user and can only be added in the SQL editor, so that is where any curated area data goes; the app does not ship any crime or hotspot data. Alerts are shown while the app is open; push notifications need background location, which is not built. The map is always 3D and north-up (two-finger drag changes the tilt). Each person's position is checked against the building outlines around them; the building they are in is highlighted green, with "Inside", "Near building" or "Outside" on their card. The check is probabilistic rather than a single point-in-polygon test: it weighs how much of the GPS uncertainty falls in each building, how many floors it has, whether the fix is poor (a sign of being indoors) and whether the person is moving like a vehicle. Next to tall buildings the reported accuracy is inflated 1.5x, because GPS is optimistic there. A confident "Inside" needs a fix within 30 m; a worse fix gives "Likely inside", and beyond 150 m it says nothing. The answer is always one of two things: on the street (nothing highlighted) or exactly one building, even when someone is between two buildings. Someone shown inside a building is drawn on that building rather than at the noisy GPS point, and a person standing still is placed at the median of their last nine readings so a run of wild ones cannot move them. Walking pace counts as evidence for the street, and a change of answer must be seen on two readings in a row before it replaces the one on screen, so it does not flicker. It can be wrong for someone standing outside in a dense city with a poor fix, and it cannot tell which floor someone is on. In development the phone's raw fixes and the per-building probabilities are logged to the Expo terminal (`[fix]`, `[presence]`). OpenFreeMap is a free public service without guarantees; before a real launch, host your own tiles or switch `STYLE_URL` there to a paid provider, and keep the attribution.
- Change `ios.bundleIdentifier` and `android.package` in [app.json](app.json) to your own before publishing.

## Enrolment and the identity check (FICA)

The order is: sign in, **choose an icon**, **verify identity**, then create or join a circle. Both steps gate the app (`src/app/_layout.tsx`); a person whose submission is *pending* review is let through, one who is *rejected* is asked to submit again.

- **Icon** ([src/components/avatar-builder.tsx](src/components/avatar-builder.tsx), [src/lib/avatar.ts](src/lib/avatar.ts)): built on the open-source [DiceBear](https://www.dicebear.com) "Lorelei" style (artwork by Lisa Wischofsky, CC0; code MIT), so no attribution is required. Only the chosen options are stored (about 260 bytes, `profiles.avatar`); the picture is drawn from them everywhere: map markers, orbs, lists and the location card. Change it later in Settings.
- **Identity check** ([src/app/verify.tsx](src/app/verify.tsx)): consent, choose a document (smart ID card front and back, green ID book, or passport), photograph it with the document scanner (below), check the name and number it read, then a selfie where the person looks ahead and turns their head left and right (in a random order). The ID number is checked on the phone (13 digits, real date, check digit; [src/lib/id-number.ts](src/lib/id-number.ts)). The photos go to the private `kyc` bucket and the record to `kyc_submissions` (see [supabase/enrolment.sql](supabase/enrolment.sql)); the app can read only the person's own row, and it cannot read the photos back. The ID screens block screenshots and the phone's copies are deleted after upload. If the scanner cannot start, a basic camera (manual shutter, no reading) is offered instead.
- **Head-turn check** ([src/components/liveness-html.ts](src/components/liveness-html.ts)): Google's MediaPipe Face Landmarker running in a WebView reads the head's yaw from the camera; each turn must pass 20 degrees and the person must return to centre in between. It needs internet (the model and script load from jsDelivr / Google storage), and the front camera through the WebView. Tested against the real model with turned-face photos and a fake webcam; **not yet run on a real Android phone in Expo Go**.
- **Document scanner** ([src/components/id-scanner.tsx](src/components/id-scanner.tsx), page in [src/components/id-scanner-html.ts](src/components/id-scanner-html.ts)): the back camera runs in a WebView page that finds the document (a rectangle of the right shape whose four edges are visible, searched around the on-screen frame, tolerant of a few degrees of tilt and of one faint edge), checks focus, glare and light inside it, and takes the photo by itself after about 0.7 s of holding still, cropped to the card and straightened. The guide frame turns amber then green with a progress ring, shows a faint picture of what is wanted, and the hints are specific ("Move a little closer", "Tilt it slightly to avoid the glare", "Hold still"). "Take photo now" appears after 12 s and a "use the basic camera" link after 30 s. It then reads the text with [Tesseract.js](https://github.com/naptha/tesseract.js) (started in the background while the person lines the card up): a South African ID number only counts if its date and check digit are valid ([src/lib/id-parse.ts](src/lib/id-parse.ts)), passports are read from their machine-readable lines with the ICAO check digits verified, and the name and number are pre-filled for the person to correct. What was read, and whether it matches what was typed, is saved in `kyc_submissions.scan` for the reviewer. Tested against synthetic ID cards in many conditions (well placed, too far, too close, off-centre, blurred, glare, dark, over-exposed, moving, tilted, on light and dark desks): **never tried on a real card or a real phone camera**, so the thresholds may need tuning (they are constants at the top of the page).
- **Live-face check** (part of the selfie page): while the person looks straight ahead, Minivision's [Silent-Face-Anti-Spoofing](https://github.com/minivision-ai/Silent-Face-Anti-Spoofing) models (Apache-2.0; `assets/models/`, see `NOTICE.md`), converted to ONNX and run with ONNX Runtime Web, score a few frames for a printed photo or a screen held to the camera. The pipeline follows the project's own code and reproduces its results on its sample images (real face 0.99 real, the two spoof samples flagged). Fewer than 0.6 live probability on average is a failed try; after two failed tries the person can continue and the submission is flagged (`liveness.antiSpoof.reviewFlag`) for a person to look at. It runs on the phone, so a determined attacker can bypass it; for real assurance re-run the same models on the uploaded selfie on a server, or use a verification provider.
- **Runtime downloads:** the selfie and scanner pages load MediaPipe, Tesseract.js (about 7 MB with its language data) and ONNX Runtime Web (about 14 MB) from jsDelivr and Google storage the first time, so they need internet. Self-host these before production.
- **Other SDKs considered:** [KBY-AI's ID Card Recognition SDK](https://github.com/kby-ai/IDCard-Recognition-SDK) is a commercial product: it needs a licence key from KBY-AI, is native (Android, iOS, Flutter) or a Linux server, and has no React Native or Expo module, so it is not used. It could be added later as a server-side check. Never send real IDs to its public demo endpoint.
- **What this is not:** it does not check the ID against Home Affairs, match the selfie to the ID photo, or reliably detect a replayed video, a virtual camera or a deepfake (the live-face check catches prints and screens on an honest phone). That needs a verification provider or your own reviewers looking at the photos; until then every submission stays *pending* until you set it to *verified* in Supabase.
- Set `EXPO_PUBLIC_REQUIRE_KYC=false` to turn the gate off while developing; in development builds the intro screen also has a "Skip" link.
- The consent wording is a draft (`CONSENT_VERSION` in [src/lib/kyc.ts](src/lib/kyc.ts)); have your compliance officer review it. Under POPIA, ID photos and face images are sensitive personal information, and FICA record-keeping (generally five years) can conflict with deleting an account: deleting the account removes the database row but not the stored photos.

## Layout

- `src/app` – screens (expo-router): sign-in, avatar, verify, onboarding, and the Map / Family / Settings tabs
- `src/components/auth-ui.tsx` – the sign-in and onboarding look: black on white (white on black in dark mode), ring-of-dots mark, pill buttons, floating-label pill fields. Colours are `authPalette` in [src/constants/theme.ts](src/constants/theme.ts); the rest of the app keeps its own teal theme.
- `src/providers` – auth session and circle state (members, live locations, sharing engine)
- `src/lib/location.ts` – foreground watcher, background task, permissions
- `supabase/schema.sql` – tables, RLS policies, RPCs
